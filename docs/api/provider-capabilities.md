# Provider Capabilities

Side-by-side comparison of the five first-party AI providers shipped
as standalone npm packages under `@genoffice/provider-*`.

## At-a-glance

| Capability | Anthropic | OpenAI | Gemini | OpenAI-compat | Ollama |
|---|---|---|---|---|---|
| npm package | `@genoffice/provider-anthropic` | `@genoffice/provider-openai` | `@genoffice/provider-gemini` | `@genoffice/provider-openai-compatible` | `@genoffice/provider-ollama` |
| Plugin id | `anthropic` | `openai` | `gemini` | `openai-compatible` | `ollama` |
| API style | Native Anthropic Messages | Native OpenAI Chat | Native Gemini `generateContent` | OpenAI Chat (templated) | OpenAI Chat (templated) |
| One-shot chat | ✅ | ✅ | ✅ | ✅ | ✅ |
| Stream chat (SSE) | ✅ | ✅ | ✅ | ✅ | ✅ |
| Tool / function calling | ✅ | ✅ | ✅ | ✅ | ⚠️ host-dependent |
| System prompt | ✅ | ✅ | ✅ | ✅ | ✅ |
| Multi-turn conversation | ✅ | ✅ | ✅ | ✅ | ✅ |
| Image input (vision) | ✅ | ✅ | ✅ | ⚠️ host-dependent | ⚠️ host-dependent |
| Image generation | ❌ | ❌ | ❌ (out-of-scope) | ❌ | ❌ |
| Web search tool | ❌ | ❌ | ❌ | ❌ | ❌ |
| Custom `baseUrl` | ❌ | ❌ | ❌ | ✅ | ✅ |
| Self-hostable | ❌ | ❌ | ❌ | ⚠️ depends on host | ✅ (localhost) |
| API key required | ✅ | ✅ | ✅ | ✅ | ❌ (no key) |

_DeepSeek and Kimi provide the same capabilities as OpenAI-compat (chat / stream / tool use / system prompt / multi-turn); their defaults match the OpenAI-compat column above. DeepSeek's `deepseek-reasoner` exposes reasoning content in addition to standard chat._

## Use-case guidance

- **Long-context reasoning, agentic loops** → Anthropic Claude Opus 4.6 (200K+ context, strong tool use).
- **Cheap high-throughput chat** → OpenAI gpt-4o-mini or Gemini 2.0 Flash.
- **Multimodal (image + text)** → Anthropic / OpenAI / Gemini all support vision input.
- **Local / air-gapped / cost-zero** → Ollama (auto-detects installed models).
- **Bring-your-own OpenAI-compatible endpoint** → OpenAI-compatible factory.

## How to register a custom provider

Two routes:

1. **Spread-and-override** an existing compatible plugin:
   ```ts
   import compatible from '@genoffice/provider-openai-compatible'
   registry.register({
     ...compatible,
     id: 'together',
     label: 'Together.ai',
     models: ['meta-llama/Llama-3.1-70B-Instruct-Turbo'],
     defaultModel: 'meta-llama/Llama-3.1-70B-Instruct-Turbo',
     keyPlaceholder: 'tk-…',
     needsBaseUrl: true,
   })
   ```
2. **Author a standalone npm package** that implements `AiProviderPlugin`
   and publish under `@genoffice/provider-<your-provider>`. See
   [Provider Plugins](/api/provider-plugins).

## When the matrix changes

If you add a new provider or capability to an existing one, update this
page. The Capability snapshot is regenerated by hand on every minor
version bump — the row "API style" must reflect the actual transport
(`/v1/messages` vs `/v1/chat/completions` vs `:generateContent`).
